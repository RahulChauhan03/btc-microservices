Project Questions

1. Explain your project in one minute.
It is a business travel and claim management application using Angular frontend and Spring Boot microservices. Users can log in, manage trips, expenses, claims, and users. Gateway is the single entry point, Eureka handles discovery, Config Server centralizes configuration, and each domain service owns its MySQL database.
2. Why did you use microservices?
To separate business domains, allow independent deployment, scale services separately, and keep ownership clear for user, trip, expense, and claim modules.
3. What is the role of API Gateway?
It routes all client requests to the correct service, centralizes CORS and cross-cutting concerns, and hides internal service URLs from the frontend.
4. How does service discovery work here?
Services register with Eureka. Gateway uses logical names like USER-SERVICE and Eureka resolves them to running service instances.
5. What does Config Server do?
It stores common and service-specific properties such as ports, database URLs, JPA settings, and actuator exposure in one central place.
6. What are your main backend modules?
User/Auth service, Trip service, Expense service, Claim service, API Gateway, Eureka registry, and Config Server.
7. What are your main frontend modules?
Login, dashboard, trips, expenses, claims, users, shared data table, confirmation dialog, loading overlay, guards, services, and interceptors.
8. Which REST APIs did you build?
CRUD APIs for users, trips, expenses, and claims, plus /auth/login for authentication.
9. How is authentication handled?
The user service validates email and BCrypt password, creates a simple JWT-like token, and Angular stores it in local or session storage.
10. Is your token production-ready?
No. It is a learning/demo token with alg:none. In production I would use signed JWT with secret/private key, Spring Security filters, refresh tokens, and token validation at the gateway or services.
11. How do Angular requests include authentication?
An HTTP interceptor reads the token from AuthService and adds Authorization: Bearer token to outgoing requests.
12. How do you protect routes in Angular?
authGuard blocks unauthenticated users, guestGuard redirects logged-in users away from login, and adminGuard protects user management.
13. How is error handling done?
Backend services use custom exceptions and global exception handlers. Frontend uses an error interceptor to show toast messages and logout on 401.
14. How is loading state handled?
Angular loading interceptor increments/decrements an active request counter in LoadingService, exposed as a signal.
15. Why use DTOs?
DTOs separate API request/response shape from entities, avoid exposing internal fields like password hash, and allow validation at the boundary.
16. What validations exist?
Required fields use @NotBlank/@NotNull, money fields use @PositiveOrZero, and unique values are checked in services and database columns.
17. How do you avoid duplicate users?
The user entity has unique email and service logic checks existsByEmail before insert.
18. How do you avoid duplicate trips or claims?
Trips use unique tripCode; claims use unique claimNumber; both are checked before create/update.
19. Why does each service have its own database?
It follows database-per-service ownership, reducing coupling and allowing independent schema changes.
20. How would services communicate if needed?
Synchronous REST through service discovery for direct lookups, or asynchronous events/message queue for workflows like claim approved -> payment -> notification.
21. What is the start order?
Config Server, Eureka Registry, domain services, API Gateway, then Angular frontend.
22. What is the biggest improvement you would add?
Real Spring Security JWT validation, Docker Compose, centralized logging, pagination, and message-driven payment/notification flows.
23. How would you monitor this system?
Use Spring Actuator, centralized logs, metrics with Prometheus/Grafana, distributed tracing, and gateway-level request monitoring.
24. How would you deploy it?
Build each service as a Docker image, use environment variables for configs, run through Docker Compose/Kubernetes, and put gateway behind a load balancer.
25. What challenge did you face?
Coordinating service ports, gateway routes, CORS, and frontend API paths. I solved it using centralized config and Gateway route mapping.

Java Questions

1. Why Java 17?
It is an LTS version with modern language features, better performance, and strong Spring Boot support.
2. What are OOP principles?
Encapsulation, inheritance, polymorphism, and abstraction.
3. Explain encapsulation in your project.
Entity fields are accessed through Lombok getters/setters, and service logic hides repository details from controllers.
4. What is polymorphism?
Same interface or method call can behave differently based on implementation or object type.
5. Abstract class vs interface?
Interface defines contract; abstract class can share state and partial implementation. For service contracts, interfaces are preferred.
6. What is JVM?
JVM runs Java bytecode and provides memory management, garbage collection, and platform independence.
7. JDK vs JRE vs JVM?
JDK builds Java apps, JRE runs Java apps, JVM executes bytecode inside the runtime.
8. What is garbage collection?
Automatic memory cleanup for objects that are no longer reachable.
9. Stack vs heap?
Stack stores method frames and local references; heap stores objects.
10. == vs equals?
== compares references for objects; equals compares logical equality when implemented.
11. hashCode contract?
Equal objects must have same hashCode. It is important for HashMap and HashSet.
12. ArrayList vs LinkedList?
ArrayList is faster for random access; LinkedList is better for frequent middle insert/delete, but ArrayList is usually preferred.
13. HashMap vs ConcurrentHashMap?
HashMap is not thread-safe; ConcurrentHashMap supports safe concurrent access with better locking strategy.
14. What is immutable class?
A class whose object state cannot change after creation, like String.
15. Why String is immutable?
For security, caching, thread safety, and reliable hashCode usage.
16. StringBuilder vs StringBuffer?
StringBuilder is faster and not synchronized; StringBuffer is synchronized.
17. Checked vs unchecked exceptions?
Checked exceptions must be handled or declared; unchecked exceptions extend RuntimeException.
18. What exceptions do you use?
Custom runtime exceptions like UserNotFoundException, DuplicateResourceException, and InvalidCredentialsException.
19. What is Optional?
A container that may or may not hold a value, used to avoid direct null handling.
20. What is Stream API?
A functional style API for processing collections with map, filter, reduce, and collect/toList.
21. Where did you use streams?
In service methods to map entity lists to response DTO lists.
22. Lambda expression?
A short anonymous function used with functional interfaces.
23. What is dependency injection?
Objects receive dependencies from the framework instead of creating them manually.
24. final keyword?
For variables it prevents reassignment; for methods overriding; for classes inheritance.
25. static keyword?
Belongs to class rather than object instance.
26. What is serialization?
Converting object state to bytes or text for storage/transfer; JSON serialization is common in REST APIs.
27. What is thread?
A lightweight execution path inside a process.
28. synchronized keyword?
It restricts access to a block or method so only one thread executes it at a time.
29. What is BigDecimal?
A precise decimal type used for money values like budget, expenses, and claim amount.
30. Why use LocalDate and LocalDateTime?
They are modern Java time APIs; LocalDate for dates, LocalDateTime for timestamp fields.

Spring Boot Questions

1. What is Spring Boot?
A framework that simplifies Spring application setup using auto-configuration, starters, and embedded servers.
2. What is auto-configuration?
Spring Boot configures beans automatically based on classpath dependencies and properties.
3. What is starter dependency?
A bundled dependency set for a feature, like web, data-jpa, validation, or actuator.
4. @SpringBootApplication?
Combines configuration, component scanning, and auto-configuration.
5. @RestController?
Marks a class as REST controller and returns JSON responses directly.
6. @RequestMapping?
Defines base URL path or HTTP mapping for controller methods/classes.
7. @Service?
Marks business logic classes as Spring-managed service beans.
8. @Repository?
Marks persistence layer beans; Spring Data JPA repositories are generated from interfaces.
9. @Entity?
Maps a Java class to a database table.
10. @Transactional?
Runs method logic inside a database transaction and rolls back on runtime exceptions.
11. Why readOnly transaction?
It optimizes read operations and communicates that no changes should be persisted.
12. What is JPA?
A Java specification for ORM, mapping objects to relational database tables.
13. What is Hibernate?
The common JPA implementation used by Spring Boot Data JPA.
14. What is JpaRepository?
It provides ready-made CRUD and pagination methods for entities.
15. What is derived query method?
Spring Data creates queries from method names like existsByEmail.
16. What is ddl-auto=update?
Hibernate updates schema automatically from entities. Good for development, but Flyway/Liquibase is better in production.
17. What is Bean Validation?
Validation annotations like @NotBlank run on request DTOs when using @Valid.
18. How do you return 201 Created?
Use ResponseEntity.status(HttpStatus.CREATED).body(response) after create.
19. How do you handle 404?
Throw custom NotFoundException and map it in a global exception handler.
20. What is GlobalExceptionHandler?
A centralized class with @ControllerAdvice that converts exceptions to consistent error responses.
21. What is BCrypt?
A secure password hashing algorithm with salt and work factor.
22. Why not store plain passwords?
If the database leaks, plain passwords expose users. Hashing reduces damage.
23. What is Spring Cloud Gateway?
A reactive API gateway for routing, filters, CORS, and cross-cutting request handling.
24. What is Eureka?
A service registry where services register and clients discover service instances dynamically.
25. What is Config Server?
A centralized external configuration server for multiple services.
26. What is Actuator?
Production-ready endpoints for health, info, metrics, and monitoring.
27. Why use OpenAPI?
To generate interactive API documentation and make testing easier.
28. What is Lombok?
A compile-time annotation library to reduce boilerplate like getters, setters, builders, and constructors.
29. Why constructor injection?
It makes dependencies explicit, supports immutability, and is easier to test.
30. What is CORS?
Browser security policy controlling cross-origin requests. Gateway config allows frontend calls to backend APIs.
31. How would you secure services?
Use Spring Security JWT filters, validate tokens, role-based authorization, HTTPS, and restrict direct service access.
32. How would you add pagination?
Use Pageable in repository/controller and return Page<DTO> or a custom page response.
33. How do you test controllers?
Use MockMvc or WebTestClient with mocked services for request/response validation.
34. How do you test services?
Use JUnit and Mockito for business logic, plus integration tests for repository/database behavior.
35. What is the difference between monolith and microservices?
A monolith deploys one application; microservices split domains into independently deployable services.

Angular Questions

1. What is Angular?
A TypeScript framework for building component-based single-page applications.
2. What Angular version is used?
Angular 21 with standalone components/routes, signals, Angular Material, and RxJS.
3. What is a component?
A UI building block with TypeScript logic, HTML template, and CSS styles.
4. What is service in Angular?
A reusable class for shared logic like API calls, authentication, loading, and toast messages.
5. What is dependency injection?
Angular provides required services to components/classes instead of manual object creation.
6. What is lazy loading?
Loading route modules/components only when needed, improving initial load time.
7. Where is lazy loading used?
Login, dashboard, trips, expenses, claims, and users routes use loadChildren or loadComponent.
8. What is Angular Router?
It maps browser URLs to components and supports guards, redirects, and lazy routes.
9. What are route guards?
Functions/classes that decide whether navigation is allowed.
10. What is HttpClient?
Angular service for calling REST APIs and receiving typed Observables.
11. What is interceptor?
A function/class that processes HTTP requests or responses globally.
12. Which interceptors are used?
Auth token, error handling, and loading interceptors.
13. What is RxJS Observable?
A stream that emits async values, commonly used for HTTP responses and events.
14. Observable vs Promise?
Promise emits once; Observable can emit multiple values, can be cancelled, and supports operators.
15. What is subscribe?
It starts listening to an Observable and handles next/error/complete callbacks.
16. What is signal?
A reactive state primitive. This project uses signals for auth user/token and loading state.
17. What is computed signal?
A derived value that updates when dependent signals change, like isAuthenticated.
18. What is localStorage vs sessionStorage?
localStorage persists after browser close; sessionStorage clears when tab/session ends.
19. How is remember me implemented?
If selected, token/user go to localStorage; otherwise to sessionStorage.
20. What is Angular Material?
A UI component library used for dialogs, snack bars, and polished UI components.
21. What is two-way binding?
Binding where UI changes update component state and state changes update UI, usually with ngModel.
22. Reactive forms vs template forms?
Reactive forms are model-driven and easier for complex validation; template forms are simpler for small forms.
23. What is TypeScript interface?
A compile-time contract for object shape, used for User, Trip, Expense, Claim, and auth models.
24. What is environment file?
It stores environment-specific values like backend API base URL.
25. How do you handle API errors?
The error interceptor extracts message and displays it using ToastService.
26. How do you avoid duplicate CRUD code?
CrudHttpService provides generic list, create, update, and delete methods.
27. What is standalone component?
A component that declares its imports directly and does not require NgModule.
28. How do you improve frontend performance?
Lazy loading, trackBy in lists, OnPush/change detection optimization, caching, and reducing bundle size.
29. How do you secure Angular app?
Use route guards, token handling, HTTPS, avoid sensitive data in storage when possible, and enforce security on backend too.
30. What is SPA?
Single Page Application loads once and updates views client-side without full page reloads.

SQL and Database Questions

1. Which database is used?
MySQL, with separate databases for user, trip, expense, and claim services.
2. What is primary key?
A unique identifier for each row, such as auto-generated id.
3. What is foreign key?
A column that references a primary key in another table to enforce relationship integrity.
4. What is unique constraint?
It prevents duplicate values, used for user email, trip code, and claim number.
5. What is normalization?
Organizing data to reduce duplication and improve consistency.
6. What is denormalization?
Adding controlled duplication to improve read performance.
7. What is index?
A data structure that improves search/filter speed but adds write overhead.
8. Where would you add indexes?
On email, tripCode, claimNumber, status, expenseDate, and frequently filtered columns.
9. What is transaction?
A group of DB operations executed atomically: all succeed or all rollback.
10. ACID properties?
Atomicity, Consistency, Isolation, Durability.
11. INNER JOIN vs LEFT JOIN?
INNER JOIN returns matching rows only; LEFT JOIN returns all left table rows plus matches.
12. WHERE vs HAVING?
WHERE filters rows before grouping; HAVING filters groups after aggregation.
13. DELETE vs TRUNCATE?
DELETE removes selected rows and can rollback; TRUNCATE removes all rows faster and resets identity in many DBs.
14. CHAR vs VARCHAR?
CHAR is fixed length; VARCHAR is variable length.
15. Why use DECIMAL for money?
It avoids floating point precision errors.
16. What is SQL injection?
An attack where malicious SQL is inserted into inputs. Prepared statements/JPA parameters prevent it.
17. What is pagination query?
Use LIMIT and OFFSET, or Spring Data Pageable.
18. Query: total expense amount by category?
SELECT category, SUM(amount) FROM expenses GROUP BY category;
19. Query: pending claims count?
SELECT COUNT(*) FROM claims WHERE status='PENDING';
20. Query: trips ordered by start date?
SELECT * FROM trips ORDER BY start_date DESC;
21. Query: find duplicate emails?
SELECT email, COUNT(*) FROM users GROUP BY email HAVING COUNT(*) > 1;
22. What is isolation level?
It controls how transactions see changes from other transactions.
23. Dirty read?
Reading uncommitted data from another transaction.
24. Non-repeatable read?
Same row read twice gives different values because another transaction committed updates.
25. Phantom read?
Same query returns different row set because another transaction inserted/deleted rows.
26. What is N+1 problem?
ORM executes one query for parent rows and additional queries for each child row. Use joins/entity graphs/fetch strategies.
27. What is migration tool?
Flyway or Liquibase manages schema versioning instead of relying on ddl-auto update.
28. How do you backup DB?
Use scheduled dumps/snapshots, point-in-time recovery, and test restore process.
29. How do you improve slow queries?
Analyze execution plan, add indexes, reduce selected columns, paginate, and avoid unnecessary joins.
30. What is database-per-service challenge?
Cross-service joins are not direct; use APIs, events, read models, or reporting databases.

System Design Questions

1. Draw your architecture.
Angular -> API Gateway -> Eureka-discovered services -> separate MySQL DBs. Config Server supplies properties to services.
2. Why Gateway as single entry point?
It simplifies client integration and centralizes routing, CORS, auth, logging, and rate limiting.
3. How would you scale this app?
Run multiple instances of high-traffic services, let Eureka register them, and Gateway load-balances via lb://.
4. How would you handle service failure?
Use retries, timeouts, circuit breakers, fallback responses, and monitoring alerts.
5. What is circuit breaker?
A pattern that stops calls to failing service temporarily to avoid cascading failures.
6. How would claim approval work?
Claim service changes status, publishes event, payment service processes reimbursement, notification service informs user.
7. Sync vs async communication?
Sync REST is simple for immediate responses; async messaging is better for long-running workflows and resilience.
8. How would you ensure consistency across services?
Use saga pattern and events instead of distributed transactions.
9. What is saga pattern?
A sequence of local transactions with compensating actions if a later step fails.
10. How would you design authentication?
User service issues signed JWT, Gateway validates token, services enforce role/permission where needed.
11. How would you do authorization?
Use roles like ADMIN, MANAGER, EMPLOYEE and method/route-level access rules.
12. How would you store files/receipts?
Store files in object storage like S3 and save metadata/URL in Expense or Claim service.
13. How would dashboard data be built?
Either aggregate by calling services or maintain a read-optimized dashboard/reporting model through events.
14. How would you add search?
Basic DB indexes for small scale; Elasticsearch/OpenSearch for advanced text search and filters.
15. How would you add pagination?
API accepts page, size, sort; repository returns paginated results; frontend table consumes metadata.
16. How would you prevent duplicate requests?
Use idempotency keys for create/payment APIs and unique business keys like claimNumber.
17. What is idempotency?
Same request repeated multiple times produces the same result without duplicate side effects.
18. How would you handle rate limiting?
Add gateway-level rate limiting per user/IP using Redis-backed counters.
19. How would you log requests?
Use gateway filters, correlation IDs, structured JSON logs, and centralized log storage.
20. What is correlation ID?
A unique request ID passed across services to trace one user request end-to-end.
21. How would you monitor latency?
Actuator metrics plus Prometheus/Grafana and distributed tracing with Zipkin/Tempo/Jaeger.
22. How would you secure configs?
Use environment variables, vault/secret manager, encrypted config values, and never commit real passwords.
23. What is database sharding?
Splitting data across multiple DB nodes by key to handle high scale.
24. What is caching?
Storing frequently used data in memory like Redis to reduce DB/API load.
25. What would you cache?
User profile/role, dashboard summaries, dropdown/master data, and rarely changing lookup values.
26. How would you invalidate cache?
Use TTL and explicit eviction after updates.
27. How would you design notifications?
Consume events from queue, render template, send email/SMS, retry failures, and store delivery status.
28. How would you design payments?
Payment service receives approved claim event, creates payment record, calls provider, handles callback, and updates status.
29. How would you make it production-ready?
Docker, CI/CD, signed JWT, migration scripts, tests, logs, metrics, tracing, secrets management, and HTTPS.
30. What are microservice tradeoffs?
Pros: scalability and separation. Cons: operational complexity, network failure, data consistency, and monitoring complexity.

DSA Questions Based on This Project

1. Which DSA topics are most relevant?
Arrays/lists, hash maps, strings, sorting, searching, queues, heaps, trees, graphs, and basic dynamic programming.
2. Find duplicate emails in a user list.
Use HashSet. If email already exists, it is duplicate. Time O(n), space O(n).
3. Group expenses by category.
Use HashMap category -> total amount. Time O(n).
4. Sort trips by start date.
Use comparator on startDate. Time O(n log n).
5. Search claim by claimNumber.
For repeated lookup, use HashMap claimNumber -> Claim for O(1) average search.
6. Find top 3 highest expenses.
Use min heap of size 3. Time O(n log k).
7. Find total monthly expenses.
Iterate expenses, filter by month/year, sum amount. Time O(n).
8. Detect overlapping trips.
Sort by start date; overlap exists if current start <= previous end.
9. Validate balanced brackets in expression.
Use stack; push opening brackets, match closing brackets. Time O(n).
10. Implement LRU cache.
Use HashMap plus doubly linked list for O(1) get/put.
11. BFS use case?
Find shortest path in unweighted graph, like approval hierarchy levels.
12. DFS use case?
Traverse dependency graph or organizational tree recursively.
13. Binary search use case?
Search sorted trip dates or amounts in O(log n).
14. Two-pointer use case?
Pair expenses/trips after sorting, or check intervals efficiently.
15. Sliding window use case?
Find max expense total in any 7-day period.
16. Queue use case?
Process notifications or jobs in FIFO order.
17. Stack use case?
Undo operations or expression validation.
18. Heap use case?
Top K expenses, latest pending claims, or priority notifications.
19. Trie use case?
Autocomplete employee names, trip codes, or destinations.
20. Graph use case?
Approval workflow, service dependency map, or route planning.
21. Time complexity of HashMap lookup?
Average O(1), worst O(n) but improved with tree bins in modern Java for collisions.
22. Time complexity of sorting?
Usually O(n log n).
23. Reverse a string.
Use two pointers swapping characters, or StringBuilder reverse.
24. Check palindrome.
Use two pointers from both ends and compare characters.
25. First non-repeating character.
Count characters with LinkedHashMap, then return first with count 1.
26. Merge two sorted lists.
Use two pointers and append smaller item each time. Time O(n+m).
27. Find missing number from 1..n.
Use expected sum n(n+1)/2 minus actual sum, or XOR.
28. Remove duplicates from array.
Use HashSet, or two pointers if sorted.
29. Count API hits per user.
Use HashMap userId -> count; for time windows use queue/timestamps or Redis sorted sets.
30. Design rate limiter DSA.
Token bucket or sliding window counter using queue/map per user.

Short Closing Pitch

My project is a Spring Boot and Angular microservices application for business travel, expenses, and claims. I implemented separate services with REST APIs, DTO validation, JPA persistence, Eureka discovery, centralized configuration, and API Gateway routing. On the frontend I used Angular routes, guards, interceptors, services, signals, and Angular Material to build secured CRUD screens. If I take this to production, I would strengthen JWT security, add Docker/CI-CD, pagination, observability, migration scripts, and event-driven payment/notification workflows.
